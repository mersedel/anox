# ANOX

[English](README.md) · **Українська**

Консольний чат клієнт–сервер на C# (.NET 10). Користувачі реєструються під іменем, надсилають один одному запити на чат і переписуються в приватних сесіях один на один.

## Структура

| Проєкт | Що робить |
|---|---|
| `ANOX.Server` | TCP-сервер: реєстрація, сесії, запити на чат, серверні команди |
| `ANOX.Client` | Консольний клієнт |
| `ANOX.Core` | Спільний протокол: типи повідомлень, серіалізація, валідація |
| `ANOX.Logger` | Логування в консоль і файл |

## Запуск

Потрібен [.NET 10 SDK](https://dotnet.microsoft.com/download).

```bash
dotnet build anox.slnx
```

### Сервер

```bash
dotnet run --project ANOX.Server
```

Під час першого запуску поряд з виконуваним файлом створюється `server.json` зі значеннями за замовчуванням. Шлях до іншого файлу можна передати так: `--config <path>`.

### Клієнт

```bash
dotnet run --project ANOX.Client
```

За замовчуванням клієнт підключається до `anox.ddns.net:5656`. Щоб підключитися до іншого сервера, наприклад до локального для тестування, передайте його адресу аргументом: `AnoxClient <host>[:port]` або `AnoxClient <host> <port>`.

```bash
dotnet run --project ANOX.Client -- localhost
```

## Конфіг сервера (`server.json`)

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `Host` | `0.0.0.0` | IP, на якому слухати (`0.0.0.0` означає всі інтерфейси) |
| `Port` | `5656` | Порт |
| `AdminPasswordHash` | *(порожньо)* | Хеш пароля для `/login`; якщо порожньо, адмінка вимкнена |
| `MaxLoginAttempts` | `5` | Скільки разів можна ввести неправильний пароль до блокування |
| `LoginLockoutSeconds` | `60` | Тривалість блокування (рахується по IP) |
| `InviteTimeoutSeconds` | `60` | Через скільки запит на чат стає недійсним |
| `InviteSameUserCooldownSeconds` | `15` | Пауза перед повторним запитом тій самій людині |
| `InviteRateWindowSeconds` | `60` | Вікно для ліміту запитів |
| `MaxInvitesPerWindow` | `5` | Максимум запитів на чат за це вікно |
| `MaxMessageLength` | `2000` | Максимальна довжина повідомлення в символах |
| `RegisterTimeoutSeconds` | `10` | Нове з'єднання, яке не зареєструвалось вчасно, закривається |
| `MaxConnections` | `500` | Скільки всього відкритих з'єднань дозволено |
| `MaxConnectionsPerIp` | `5` | Скільки з'єднань дозволено з однієї IP (IPv6: на /64) |
| `SendTimeoutSeconds` | `10` | Клієнт, який стільки часу не читає дані, відключається |
| `MaxMessagesPerSecond` | `5` | Середня кількість повідомлень за секунду на з'єднання; зайві відкидаються |
| `MessageBurst` | `20` | Скільки повідомлень можна надіслати короткою пачкою понад цей темп |
| `MaxProtocolViolations` | `10` | Скільки некоректних повідомлень терпимо, перш ніж закрити з'єднання |
| `LogFilePath` | `logs/server.log` | Файл логів; якщо порожньо, логи йдуть лише в консоль |

### Пароль адміна

```bash
dotnet run --project ANOX.Server -- --hash-password
```

Команда двічі попросить пароль (символи не відображаються) і виведе хеш (PBKDF2-SHA256). Вставте його в `AdminPasswordHash` і перезапустіть сервер. Сам пароль ніде не зберігається.

## Деплой

Публічний сервер працює на інстансі AWS (Ubuntu, ARM64), доступному як `anox.ddns.net`. Розгортається він із машини розробника скриптом `deploy.ps1`.

### Як влаштований сервер

| Що | Де |
|---|---|
| Програма | `/opt/anox/`: лише результат збірки; замінюється при кожному деплої |
| Конфіг | `/etc/anox/server.json`: лежить окремо від програми, тому деплой його не перезаписує |
| Сервіс | `/etc/systemd/system/anox.service` |
| Логи | журнал systemd (`LogFilePath` порожній, тож сервер пише в консоль, а journald це збирає) |

- Сервер працює від окремого системного користувача `anox`. Увійти під ним не можна (`nologin`), а все в `/opt/anox` і `/etc/anox` належить `root`: сервіс може читати свою програму й конфіг, але не змінювати їх.
- Unit додатково обмежує сервіс: `ProtectSystem=strict` (уся файлова система для нього лише для читання), `ProtectHome`, `PrivateTmp`, `NoNewPrivileges`. Через `ProtectSystem=strict` писати лог-файл нікуди, тому логування у файл вимкнене.
- systemd запускає сервер під час завантаження системи і перезапускає його через 5 секунд після падіння (`Restart=on-failure`).
- Збірка залежить від встановленого .NET (`--self-contained false`), тому рантайм .NET 10 стоїть на самому сервері. Коли проєкт переходить на нову версію .NET, спершу оновіть рантайм там.

### Доступ по SSH

`deploy.ps1` і команди нижче звертаються до SSH-хоста `anox`. Додайте його в `~/.ssh/config`:

```
Host anox
    HostName anox.ddns.net
    User ubuntu
    IdentityFile ~/.ssh/<key>.pem
```

`ubuntu` — адмінський акаунт інстансу (з `sudo`), під ним і заходимо. Користувач `anox` лише запускає сервіс.

### Деплой

```powershell
.\deploy.ps1
```

Скрипт:

1. збирає `ANOX.Server` під `linux-arm64` у `publish\server`;
2. очищає на сервері папку для завантаження `~/anox-upload`;
3. завантажує туди збірку через `scp`;
4. зупиняє сервіс, копіює файли в `/opt/anox` і запускає його знову;
5. чекає 3 секунди й перевіряє, що сервіс активний; якщо ні, скрипт завершується з помилкою й підказує команду для перегляду логів.

Конфіг не завантажується. Щоб змінити налаштування, відредагуйте `/etc/anox/server.json` на сервері й перезапустіть сервіс. Поки сервіс перезапускається (кілька секунд), підключені клієнти відпадають; повернутися можна командою `/reconnect`.

### Корисні команди

```bash
ssh anox systemctl status anox
ssh anox journalctl -u anox -n 50
ssh anox journalctl -u anox -f
ssh -t anox sudoedit /etc/anox/server.json
ssh anox sudo systemctl restart anox
```

Стан, останні 50 рядків логу, логи в реальному часі, редагування конфігу, перезапуск.

## Команди клієнта

| Команда | Опис |
|---|---|
| `/help` | Список команд |
| `/connect <username>` | Надіслати запит на чат |
| `/accept [username]` | Прийняти запит (ім'я потрібне, лише якщо запитів кілька) |
| `/decline [username]` | Відхилити запит |
| `/leave` | Вийти з поточного чату |
| `/ping` | Затримка до сервера |
| `/version` | Версії клієнта, сервера та протоколу |
| `/clear` | Очистити консоль |
| `/reconnect` | Перепідключитися |
| `/exit` | Вийти |
| `//text` | Надіслати повідомлення, що починається з `/` |

Серверні команди: `/getServerStatus`, `/getServerInfo`, `/getServerTime`. Для адміна (після `/login <пароль>`) також `/getAllUsersNames` і `/getAllUsersAmount`. Будь-яку невідому клієнту команду він пересилає на сервер.

## Протокол

Кожне повідомлення займає один рядок і закінчується `\n`:

```
<MessageType>|<sender>|<receiver>|<base64(UTF-8 text)>
```

- Імена користувачів: 1–20 символів, лише літери, цифри, `_`, `-` і `.`. Імена `SERVER` і `ALL` зарезервовані.
- `Register`: ім'я передається в полі sender, версія протоколу клієнта в тексті. Якщо версія не збігається, сервер відповідає `ProtocolMismatch` і закриває з'єднання.
- `ServerError`: текст має вигляд `<код MessageErrorType>|<опис>`.
- Поточна версія протоколу: `ProtocolInfo.Version` в `ANOX.Core`. Її треба збільшувати при кожній несумісній зміні. Версія застосунку задана в `Directory.Build.props`.

> ⚠️ Трафік не шифрується. Для роботи через інтернет потрібен TLS (запланований).
